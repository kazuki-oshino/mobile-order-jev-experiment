# LOOP — 「気になる」が、出会いになる。

架空のドーナツ店のデジタル接客POC。React + TypeScript + Jevで、閲覧中に「比較する・一問聞く・提案する・見守る」から接客を選ぶ体験を実装しています。
旧アトリエ／ドラフトは撤去し、20種類の商品棚と接客係のJevに置き換えました。

## 起動

```sh
npm install
npm run dev
```

http://127.0.0.1:5173 を開きます。`.env` の `JEV_API_KEY` を使用します。
別バックエンド・DBは不要です。Viteのローカルプロキシだけが認証キーを読み、TypeSafeの公式APIへ転送します。
キーはフロントエンドやビルド成果物へ埋め込みません。

## 体験する

1. ページ上部で「接客を選ぶ」を選び、いくつか商品を眺めます。最初は見守り、Jevが役立ちそうな接客を選ぶとカードが変わります。
2. ハニー・ハグとベリー・キスを開いて閉じ、希望に「この2品の違いを比べたい」と書いてみてください。「比較する」が選ばれると、比較表を開けます。価格・食感などは商品の設定値をコードで表示します。
3. 希望に「食感について一つ質問してほしい」と書くと、質問する接客を試せます。回答は希望のチップとして残り、×で取り消せます。自由入力は回答より優先し、回答は閲覧からの推測より優先します。
4. 「今は、静かに見たい」は即時に提案を隠します。「お手伝いを再開する」で戻ります。「このお手伝いは今は不要」はその種類の接客を抑えます（再開・モード変更・記録リセットで解除）。
5. 「おすすめを表示」に切り替えると、同じ嗜好・商品スコアから従来方式の推薦を表示します。見守り指定は切り替えても維持します。
6. 「閲覧データと、Jevの判断をのぞく」で接客の候補分布・判定履歴・比較を開いた／回答した／役に立った／今は不要などの反応を確認できます。反応は直近40件をメモリ内に保持します。

スマホは商品タップで閲覧し、画面下の店員バーから接客と希望入力を開けます。キーボードのフォーカスも滞在として記録します。
比較・おすすめからローカルのバッグに追加できます。注文・決済はありません。

選択は確率的なので、同じ操作で必ず同じ接客になるわけではありません。モード切り替えは探索用の比較で、無作為化したA/Bテストではありません。

## 何をJevへ送るか

- 20商品の価格、カロリー、甘さ・濃厚さ（1〜5）、味の系統と説明。
- 酸味・苦味・香ばしさ・果実感・さっくり感・もちもち感・ふんわり感・クリーム感・彩り・こぼれやすさ（各1〜5）、重量（g）、焼き／揚げの12属性を追加。商品詳細の「味と食感をもっと見る」で確認できます。
- 18の数値条件に合う商品のID、最近見た一致商品、注目割合。商品属性から決定的に集計し、好みの確率とは区別します。
- 商品別の訪問回数、直近30秒の滞在、最近見た順序、現在の閲覧対象。
- 滞在と再訪から算出する関心量。最近の情報ほど重く、約6.5秒で指数的に減衰します。
- 選択中のフィルター、明示した希望、バッグ内の商品。
- 質問への回答、見守り指定、辞退した接客、表示モード、コードで列挙した比較対象と実行可能な接客。感想・反応の全履歴はAPIへ送りません。

カメラ・視線認識・マイクは使いません。記録はページのメモリ内だけで保持し、再読み込み／リセットで消えます。
推薦欄への注目は閲覧データに入れず、自分の推薦を根拠に同じ推薦を強化する循環を避けています。

## 約1秒ごとの判断

- 約1秒ごとに入力の変更を確認し、変化がある時だけ最新状態を送ります。同じ商品への重複イベント、同じ希望・フィルター・バッグでの再描画、経過時間だけでは再送しません。
- 入力の変更はカードへの入場・退場・再訪、ひと言の編集／クリア、フィルター変更、バッグの増減。カード上に置いたままなら判定を保ち、滞在秒数と時間減衰は次の操作で反映します。
- 18の嗜好仮説を独立したNoul、20商品の適合度をScore、接客行動をChoiceで評価します。質問する接客が可能なときは質問の種類もChoiceで同時に聞き、実際に質問するときだけ使います。通常40問、質問できないとき39問を1リクエストで評価します。
- 仮説は「甘いごほうび」「軽め」「ほろ苦さ」「果実」「ナッツとごま」「見た目」「定番」「お手頃」に加え、「さっくり」「もちもち」「ふんわり」「クリーム」「酸味」「焙煎の香り」「小腹向け」「しっかり満足」「食べやすさ」「焼き製法」。複数成立しても構いません。
- 例：もちもち感4以上、クリーム感4以上、50g以下、80g以上かつ濃厚さ4以上、こぼれやすさ2以下。ルールは商品への一致と注目割合を計算し、Jevは閲覧順・再訪・滞在・明示した希望から嗜好仮説と20商品の適合度を判断します。
- **低い甘さを低カロリーの根拠にしない**ことを明示しています。
- 推薦はJevのスコアで、フィルター内かつバッグ外の上位最大3品を選びます。接客選択モードでは「提案する」が選ばれたときに表示します。商品棚の並びは固定です。
- 比較対象は直近30秒の閲覧順から異なる2品を抽出します。フィルター外・バッグ内は対象外。比較を開いた後は対象を固定し、応答の到着で表を入れ替えません。
- 回答済みの質問・辞退済みの接客を候補から除きます。見守り指定中の候補は見守りだけです。Choiceの候補、分布、confidenceの型と範囲を検証し、不正な応答はエラーにします。confidenceは満足度や正しさの確率ではありません。
- 5表情とセリフは、Jevの判定に応じたルールで切り替えます。生成された自由文ではありません。0.55以上の支持がない場合は探索中とします。この閾値はPOC用で利用者評価は未実施です。
- 通信は常に最大1件。応答が1秒を超えると、完了後に入力が変わっていれば最新状態を送り、古いリクエストを積みません。したがって1秒ごとの結果到着は保証しません。
- カーソル放置による滞在は8秒で頭打ち。入力が未変更／非表示タブなら通信しません。明示的な一時停止・再開もできます。
- リセット、停止、条件変更後の古い応答は捨てます。回答・見守り・辞退・モード変更も入力変更と鮮度の検証に含めます。APIエラーは明示し、再開するまで連続通信を止めます。偽のAI結果には切り替えません。

## 検証

```sh
npm test
npm run build
npm run preview
```

テストは閲覧記録、関心の減衰、レスポンス検証、1秒の接客ループ、通信重複防止、60秒間の同一入力の再送防止、追加属性と数値条件、入力の変更／クリア、停止・リセット・条件変更時の古い応答破棄、エラー回復、非表示タブ休止を扱います。
実APIの合成6ケースは、開発サーバーを5173番で起動してから `node scripts/check-assistance.mjs` で確認できます。実APIを6回呼び、結果を `docs/assistance-api-check.json` に保存します。利用者評価・一般精度の測定ではありません。

`preview` もViteのプロキシを使います。静的配信だけではAPIは動きません。

## 画像・構成

- `public/images/donuts-20.png`: 5列×4行の20種類の生成ドーナツ写真。
- `public/images/jev-faces.png`: 同一の架空店員の5表情。内蔵imagegenで生成。
- `docs/image-generation.md`: 生成プロンプト。
- `src/attention.ts`: 観測データと減衰。
- `src/assistance.ts`: 接客候補・質問・実行条件。
- `src/GuideAction.tsx`: 4種類の接客カード。
- `src/jev.ts`: 実APIの質問・応答検証。
- `src/useJev.ts`: 通信・サンプリングのライフサイクル。
- `src/App.tsx`: ショーケース・店員・バッグ・観測パネル。

商品・価格・栄養数値はすべて架空です。嗜好の推測は実際の内心を測るものではありません。
実店舗、決済、注文送信、端末間同期は対象外です。
